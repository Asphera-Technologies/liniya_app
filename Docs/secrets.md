# Ключи и секреты

Коротко: **в репозиторий не попадает ничего**, а ключ, который попал внутрь
приложения, не является по-настоящему секретным. Ниже — как это устроено
сейчас и как будет правильно, когда приложение пойдёт людям.

## Как положить ключ сейчас

```bash
mkdir -p Linea/Resources
cp Config/AISecrets.example.plist Linea/Resources/AISecrets.plist
```

Открыть `Linea/Resources/AISecrets.plist` и вписать ключ в `LINEA_AI_API_KEY`.
Всё, пересобрать приложение.

Файл в `.gitignore`, в репозиторий не уедет. Папка `Linea/` синхронизирована
с проектом Xcode, поэтому файл попадает в сборку сам — ничего настраивать в
Xcode не нужно. Если файла нет, приложение работает на шаблонных текстах, а
экран «Профиль» → «Linea AI» показывает «Не настроен». Сборка на CI при этом
не ломается.

Необязательные поля в том же файле: адрес, модель и путь запроса. Значения по
умолчанию — Grok от xAI (`https://api.x.ai/v1`, модель `grok-4.6`). Их можно
поменять без правки кода, в том числе указать другого провайдера или свой
прокси.

Итог дня ходит на тот же ключ и тот же адрес. Для него есть ещё три
необязательных поля:

| Поле | По умолчанию | Что это |
|---|---|---|
| `LINEA_AI_CHECKIN_MODEL` | `grok-4.3` | модель, которая разбирает рассказ; почему она — `Docs/check-in.md` |
| `LINEA_STT_MODEL` | `grok-voice-transcribe-2.0` | распознавание речи |
| `LINEA_STT_PATH` | `stt` | путь распознавания: `stt` у xAI, `audio/transcriptions` у OpenAI и Groq |

Если файл с ключом создан раньше, добавлять эти поля не обязательно: без них
берутся значения по умолчанию.

## Почему это только для разработки

Ключ внутри приложения **достаётся из сборки любым, у кого она есть**. Файл
`.plist` лежит в бандле, бандл распаковывается, ключ виден. Это не защищается
ни обфускацией, ни Keychain: чтобы отправить запрос, приложению всё равно
нужно иметь ключ в открытом виде.

Поэтому:

- для сборки на своём телефоне и показа заказчику — так можно;
- для TestFlight среди своих — терпимо, но ключ лучше отдельный и с лимитом;
- **для App Store — нельзя**. Ключ утечёт, а счёт за токены придёт вам.

## Как будет правильно

Запросы к модели идут не из приложения, а через **свой бэкенд**:

```text
iPhone → ваш сервер (ключ здесь) → xAI / другой провайдер
```

Приложение при этом не знает никакого ключа. Оно ходит на ваш адрес, а сервер
подставляет ключ, считает лимиты и ведёт учёт расходов. Заодно провайдера
можно поменять, не выпуская новую версию приложения.

Архитектура к этому уже готова: в `Linea/Resources/AISecrets.plist` достаточно
поменять `LINEA_AI_BASE_URL` на адрес своего сервера, а `LINEA_AI_API_KEY` — на
токен пользователя вместо ключа провайдера. Решение записано как ADR-001 в
`Docs/decisions.md`.

## Общие правила по секретам в этом проекте

- Никаких ключей, паролей и токенов в коде и в коммитах. Это же записано в
  `AGENTS.md`.
- Всё, что похоже на секрет, лежит в файлах из `.gitignore`: `.env`,
  `*.p8`, `*.p12`, `*.key`, `Linea/Resources/AISecrets.plist`.
- В репозиторий кладётся только **шаблон** без значений:
  `Config/AISecrets.example.plist`, `Backend/.env.example`.
- Если ключ всё-таки попал в коммит — его недостаточно удалить следующим
  коммитом. Ключ уже в истории: нужно отозвать его у провайдера и выпустить
  новый.
- Ключи для CI, когда понадобятся, кладутся в Secrets репозитория на GitHub
  (Settings → Secrets and variables → Actions), а не в файлы.

## Что уходит наружу

Даже с настроенным ключом наружу не уходит ничего, пока пользователь не
включит «Свободный разговор» или «Итог дня через Grok» в «Профиле» →
«Linea AI». Это два отдельных согласия: в итоге дня уходит запись голоса и
личный рассказ, а не только вопрос. Что именно уходит в каждом режиме —
таблица в `Docs/check-in.md`.

Когда включит, модель получает **производные факты**, а не замеры: сколько
человек спал, какой сегодня совет по нагрузке, названия задач, ограничения
по питанию и блок памяти — факты о человеке и выжимки дней, не больше 900
токенов. Сырые данные из «Здоровья» устройство не покидают. Сам текст
запроса собирается в `AssistantService.prompt` — его видно и можно прочитать
глазами.
