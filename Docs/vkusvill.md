# ВкусВилл: что удалось и чего нельзя

Проверено вживую 16.09.2026.

## Что есть

У ВкусВилла есть **официальный MCP-эндпоинт**, открытый и без авторизации:

```
POST https://mcp001.vkusvill.ru/mcp
Content-Type: application/json
Accept: application/json, text/event-stream
```

Это обычный JSON-RPC 2.0. Восемь инструментов:

| Инструмент | Что делает |
|---|---|
| `vkusvill_products_search` | поиск товаров: id, xml_id, цена, рейтинг, состав, КБЖУ |
| `vkusvill_product_details` | подробности по id |
| `vkusvill_product_barcode` | то же по штрихкоду |
| `vkusvill_product_analogs` | аналоги товара |
| `vkusvill_products_discount` | акции |
| `vkusvill_recipes` | рецепты с составом и КБЖУ |
| `vkusvill_cart_link_create` | ссылка на корзину, до 20 позиций |
| `vkusvill_shops` | магазины, адреса, режим работы |

Ответ приходит конвертом MCP: `result.content[0].text` — это JSON строкой,
внутри `{"ok": true, "data": {"meta": …, "items": […]}}` либо
`{"ok": false, "error": {"code", "message", …}}`.

## Чего нет

**Истории заказов и аккаунта пользователя в API нет.** Узнать, что человек
реально заказал и съел, напрямую невозможно.

Отсюда следствие для продукта: «отслеживать питание при заказе» работает
только двумя путями.

1. **Корзину собирает само приложение.** Тогда Linea знает состав заказа,
   потому что сама его сформировала. Это и сделано.
2. **Пользователь сканирует штрихкод.** `vkusvill_product_barcode` отдаёт
   состав и КБЖУ. Нужна камера и экран сканера — это отдельная работа.

## Что уже работает

На экране «Питание» появилась секция «Заказ». Кнопка «Собрать корзину» берёт
подходящие продукты из профиля (за вычетом неподходящих), ищет их в каталоге,
собирает ссылку на корзину ВкусВилла и открывает её.

Код: `Linea/Data/Nutrition/VkusVillClient.swift`, вызывается из
`NutritionStore.buildCart()`.

## Ограничения, о которых надо помнить

- **Каталог жёстко лимитирует частоту.** Поиск отвечает
  `{"code": "rate_limited"}` даже на редких запросах — при проверке с сервера
  поиск не пускал шесть попыток подряд в течение шести минут, тогда как
  штрихкод и магазины отвечали сразу. Поэтому в клиенте пауза между запросами
  и потолок в пять позиций. Ошибка лимита показывается пользователю текстом,
  а не молча.
- **Наличие по адресу доставки API не отдаёт.** Корзина может собраться из
  того, чего нет в конкретном магазине.
- **Эндпоинт неофициально документирован.** Он открыт и работает, но ВкусВилл
  может поменять формат или закрыть его без предупреждения. Клиент написан
  терпимо: неизвестные поля не роняют разбор, ошибка показывается человеку.
- **Точные имена полей товара не проверены** — лимит не дал получить успешный
  ответ поиска с этого адреса. Клиент принимает несколько вариантов имён
  (`name`/`title`, `price`/`price_now`). Это первое, что стоит проверить на
  устройстве: собрать корзину и посмотреть, что попало в ссылку.

## Что дальше, если направление нравится

- Сканер штрихкода: человек сканирует то, что ест, приложение пишет КБЖУ в
  дневник. Это закрывает учёт питания без истории заказов.
- Проверка состава против ограничений: у товара есть поле состава, а у
  пользователя — список того, что не подходит. Совпадение можно показывать
  прямо в подсказке.
- Рецепты: `vkusvill_recipes` отдаёт ингредиенты и КБЖУ, из них собирается
  корзина на день.
